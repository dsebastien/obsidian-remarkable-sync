# 2026-09-23: Open-issue sweep (#41, #28, #40)

## Accomplished

- **#41** landed as-is from delize's `fix/sync-state-pruning` (cherry-picked, authorship kept): cloud-vs-cloud sync decision, strict `parseCloudTimestamp`, `DocumentListing { notebooks, complete, error }`, pruning gated on `complete`, panel banner. Owner decision: land narrow first, #28 on top.
- **#28** listing overhaul on top of #41:
  - `mapSettledWithConcurrency` (`src/utils/concurrency.ts`), cap 6, used by `listDocuments` and `downloadDocument`.
  - `requestWithRetry` in `sync-protocol.ts`: `throw: false`, retries 429/5xx/network errors, `Retry-After` (seconds or HTTP date) else 1 s·2^n, capped 30 s, 4 attempts. `fetchRootHash` still throws `{ status: 401 }` so the token-refresh path is unchanged.
  - `resolveFolderPath` returns null when a folder in the chain was unreadable; the notebook is withheld and the listing marked incomplete (so no pruning). Genuinely absent parents keep the old truncate behaviour.
  - In-memory metadata cache keyed on entry index hash; steady-state interval sync now costs one root request plus the root index.
  - `downloadDocument` fails when any blob is missing (was: partial file set processed and marked synced).

## Decisions

- Concurrency cap is a constant, not a setting. Revisit only if a user reports rmfakecloud needing lower.
- Metadata cache is in-memory only (no sync-store schema change). Persisting it, and switching the sync decision itself to the entry hash (#41 question 2, avoids re-downloads when the device merely opens a notebook), is left for a follow-up.
- #41 upgrade burst (notebooks edited on device since last sync flip to "Needs sync" at once) goes in the release notes, not behind a flag.
