# 2026-08-12

## Issue #19 — icons not loading on Android: root cause found and fixed

Report: on a Samsung tablet "the icons and buttons aren't loading text".

**Reproduced** in the live vault with `obsidian dev:mobile on` (which reports
`Platform.isMobile && Platform.isTablet`, matching the reporter's device). Every icon-only
button in the panel — the three header buttons and each row's sync button — renders as an empty
square. Folder chevrons and folder icons render fine.

### Root cause

Obsidian's mobile stylesheet contains:

```css
.is-tablet button:not(.clickable-icon) {
    padding: var(--size-4-1) var(--size-4-5);
} /* 4px 20px */
```

At 0,2,1 that outranks `.remarkable-btn-icon` at 0,1,0, so the icon buttons get `padding: 4px
20px` on mobile. Combined with the fixed `w-7` (35px) width and `box-sizing: border-box`, the
content box computes to **-40px → 0**, and the SVG — a flex item with `flex-shrink: 1` and
`min-width: auto` — is squeezed to zero width. Measured on the tablet emulation:

| element                     | before      | after     |
| --------------------------- | ----------- | --------- |
| header button icon          | `0 x 20 px` | `20 x 20` |
| row sync button icon        | `0 x 20 px` | `20 x 20` |
| folder chevron (a `<span>`) | `17 x 17`   | `17 x 17` |

The `<span>`-hosted icons were never affected — the rule only targets `button`. That asymmetry is
exactly what the reporter described.

### Fix

Add Obsidian's own `clickable-icon` class to the icon-only buttons — the exemption the selector
itself provides. Introduced `ICON_BUTTON_CLASSES` in `remarkable-panel-view.ts` so the four call
sites cannot drift apart, documented why the class is load-bearing, and added
`remarkable-panel-view.spec.ts` as a regression guard (dropping the class breaks mobile silently;
desktop is unaffected, so nothing else would catch it).

Verified on desktop after the fix: the full panel tree walk is byte-identical to before except
the class-name string. Screenshots taken both ways.

### Ruled out along the way

- **Icon names.** All names passed to `setIcon` exist at lucide `0.446.0`, the version Obsidian
  bundles. Checked each against the lucide repo at that tag.
- **Missing stylesheet.** Release 1.14.0 attaches `main.js`, `manifest.json`, `styles.css`.
- **Load failure from node builtins.** `dist/main.js` only reaches `require("node:fs"/"os"/"path")`
  inside the lazy `Platform.isDesktopApp` guard in the legacy token reader.
- **Missing image asset.** The Buy-me-a-coffee badge is inlined as a data URL.
- **Narrow-panel flex collapse in rows.** Rows already use `min-w-0` on the info column and
  `flex-shrink-0` on the checkbox, status dot and actions.
- **Hover-only controls.** No `:hover`-gated `opacity`/`visibility`/`display` anywhere.
- **Tailwind Preflight.** Removed in the same session (below), but measured as _not_ the cause:
  the bug reproduces identically with and without it.

## Dropped Tailwind Preflight from the shipped stylesheet

Found while investigating the above, fixed on its own merits rather than as a confirmed fix for
#19.

`src/styles.src.css` opened with `@import 'tailwindcss'`, which pulls in Preflight. A plugin
stylesheet is injected into the whole Obsidian document, so that reset applied app-wide, not just
to this plugin's views: `* { margin: 0; padding: 0; border: 0 solid }`, `svg { display: block }`,
`ol, ul { list-style: none }`, `button { background: transparent; color: inherit }`.

Preflight lands in `@layer base`, and unlayered rules beat layered ones regardless of specificity,
so Obsidian's own CSS neutralised most of it on desktop — which is why nobody noticed. It still
won on every element Obsidian leaves at user-agent defaults, and the mobile app's chrome is a
different DOM with more of that surface exposed.

Replaced with theme + utilities only:

```css
@import 'tailwindcss/theme' layer(theme);
@import 'tailwindcss/utilities' layer(utilities);
```

Output drops from 22.2 KB to 19.0 KB and no longer contains `@layer base`.

### Compensating for what Preflight provided

Removing a global reset means anything that silently depended on it has to be pinned. Measuring
in the live vault showed only two things did:

- **`box-sizing: border-box`.** Restored, scoped to `[class^='remarkable-']` and its descendants.
  Deliberately _not_ a blanket descendant reset: these rules are unlayered, so a
  `* { margin: 0 }` here would outrank Obsidian's own `.markdown-rendered` spacing inside the
  "What's new" release notes and wreck them.
- **Unclassed `<p>` in the panel's empty and disconnected states.** Now explicitly `m-0`, matching
  what Preflight gave them (verified: `0px` before and after).

An earlier draft also pinned two headings — the import-confirm modal's `h3` and the "What's new"
`h2` — on the assumption Preflight had flattened them to body text. **Measurement disproved that**
and the pins were reverted: Obsidian styles both headings with unlayered rules that already beat
Preflight (`h3` 19.77px/660, `h2` 21.93px/680, identical before and after). Hardcoding Tailwind
metrics there would have overridden the user's theme. Lesson: check what actually wins the cascade
before compensating for a reset.

Also worth recording: the release-notes card renders its markdown lists without bullets
(`list-style-type: none`, `padding-inline-start: 0`). That is **not** Preflight — it is unchanged
with Preflight gone. The theme sets it, and the theme's marker-drawing rule is scoped to the
reading view, which this manually-classed `.markdown-rendered` div is not inside. Pre-existing
cosmetic quirk, left alone.
