# 2026-10-01: 2.2.0 review follow-ups

## Accomplished

- 2.2.1 released (schema 4 index fix, #44/#45); see 2026-09-30.
- Follow-up "download fails forever on one missing blob":
    - `downloadDocument` counts files by unique id; an id listed twice no longer fails the notebook forever.
    - Auto-sync backs off per notebook: k-th consecutive failure skips 2^(k-1) runs (cap 16); success or a new `lastModified` resets; second failure in a row shows one notice per notebook per session. `AutoSyncDeps.processNotebook` now returns the failure reason (or null); `notify` dep added. In memory only; manual syncs unaffected.
- Follow-up "unparseable cloud timestamp": the listing logs one warning per session (per service instance).
- Follow-up "`\` in a stored target folder": kept as a separator on every platform (Windows-synced vaults would read `..\..` as an escape). Documented in `containVaultFolderPath` and Business Rules; no code change.
- Follow-up "permanently unreadable entry keeps every listing incomplete" (business rule change approved by the user):
    - `syncIdsToKeep(listing)`: prune keeps listed + `unreadableIds`; null (no pruning) when the ids are unknown. Used by auto-sync and the panel.
    - Entries whose content is unusable (no `.metadata` in the index, metadata not JSON) are remembered by hash for the session: no refetch until the hash changes. Failed requests still retry.
    - Panel: a partial refresh with the same message and unreadable ids as the previous one shows a muted one-line note instead of the red banner (`unreadableKey`).

## Decisions

- Pruning no longer needs a complete listing, only known unreadable ids (user-approved).
- Auto-sync backoff and the unusable-entry cache are in memory only.
