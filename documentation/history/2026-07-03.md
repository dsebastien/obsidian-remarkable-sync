# 2026-07-03

## Favorites auto-sync: star on the device drives what auto-syncs (GP-44)

New `autoSyncMode` setting: `'newest'` (default, prior behavior) or `'favorites'`
(every notebook starred/pinned on the reMarkable device, in any cloud folder).
Star a notebook on the tablet → auto-sync picks it up; un-star → future syncs
skip it, vault files stay. Branch `rmplugin/favorites-sync` off `main` (no stack).

### Changes

- `NotebookSummary` gains required `pinned: boolean` (`domain/notebook.ts`) +
  pure `favoriteNotebooks()` filter. Populated from `metadata.pinned === true`
  (defensive: older/self-hosted clouds may omit the field).
- `listDocuments()` summary-building extracted to a pure
  `buildNotebookSummaries()` in `services/cloud/document-summaries.ts` (+spec:
  pinned plumb-through, folder-path chain, deleted/trash filtering). The cloud
  service now only does fetching; no behavior change.
- Settings: `autoSyncNewestOnly` replaced by `autoSyncMode: 'newest' | 'favorites'`.
  Load-merge extracted from `plugin.ts` into pure `resolveSettings()`
  (`types/plugin-settings.intf.ts`, +spec): field-by-field over defaults, legacy
  `autoSyncNewestOnly` (true OR false) → `'newest'`, explicit `autoSyncMode`
  wins, corrupt values fall back to `'newest'`, syncStore never clobbered.
  Drive-by fix: the old merge dropped `imageQuality` on load (reset to 0.85
  every restart); the new merge restores it.
- `SyncAllOptions.favoritesOnly`: candidates = all pinned docs, ignores
  `folder`/`newestOnly`. Per-notebook unchanged-skip and per-page incremental
  image skip unchanged — pinned-but-idle notebooks cost nothing. Zero pinned →
  quiet no-op on silent runs. Sync-log scope label `(favorites)`; notice
  `Syncing N favorited notebook(s)...`.
- `autoSyncScopeOptions(settings)` (in `commands/sync-all-notebooks.ts`, +spec)
  is the single mode→options mapping, used by both `plugin.runAutoSync` and the
  manual command `sync-newest-notebook` (id stable; name renamed to
  "Sync auto-sync scope now").
- Settings UI (`sync-section.ts`): newest-only toggle replaced by an
  **Auto-sync scope** dropdown (Newest in source folder / Favorited notebooks);
  section re-renders on change; Source folder is disabled with an "ignored"
  hint in favorites mode.
- Docs: README + docs/configuration.md gained the (previously undocumented)
  auto-sync settings rows and an "Automatic sync" section; Business Rules
  updated (mode semantics, never-delete, legacy migration).

### Decisions

- Legacy `autoSyncNewestOnly: false` ("every notebook in the source folder")
  has no equivalent in the two-mode dropdown; it migrates to `'newest'`
  (logged to builder-feedback for manager triage — could become a third mode).
- Out of scope (per goal): `newest N in folder` count option; syncing folder
  hierarchy changes.
