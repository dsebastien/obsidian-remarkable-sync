# 2026-08-20 — Adversarial review fixes on top of the PDF/typed-text branch

Review pass over `feat/pdf-export` (the #17 stack, split into issues #20–#27),
followed by fixes for everything found. All fixes are additive to the branch;
nothing from the original work was reverted.

## Found and fixed

1. **Typed text: a mid-run insertion dropped the page's entire text (critical).**
   `sortTextItems` ordered whole items with "A before B" edges. An insertion
   into the middle of a previously typed run — the everyday "click into a
   sentence and add a word" edit — anchors both its `leftId` and `rightId`
   inside the same item, which at item granularity reads as a cycle, and the
   cycle path returns `''`. Reproduced with a two-item fixture before fixing.
   Rewritten (`text-sequence.ts`) to expand items into one unit per claimed
   position (rmscene's model) and topo-sort units with a min-heap keyed on
   CrdtId, so mid-run anchors split the run instead of cycling. Positions are
   counted in code points, not UTF-16 units, so astral-plane characters no
   longer shift every later anchor by one. Unresolvable anchors now degrade to
   "no constraint" instead of contributing to false cycles.

2. **EPUB sources were written as `Name.pdf` (major).** `renderAndWritePages`
   pushed `sourceDocument.data` through `writeDocumentPdf` regardless of
   `kind`, so an EPUB-backed document produced a `.pdf` file containing EPUB
   bytes — unopenable, and reported as success. The docs even promised the
   correct behaviour. New `writeDocumentFile` takes the extension from the
   source kind; `writeDocumentPdf` remains as the pdf case.

3. **Highlight text corrupted the annotated PDF (major).** `/Contents` was
   written with `PDFString.of`, which does no escaping: an unbalanced `)` or a
   backslash produced a malformed object (verified: pdf-lib's own lenient
   parser logs invalid-object recoveries on such a file), and non-ASCII text
   was written as raw UTF-8 read back as PDFDocEncoding. Now
   `PDFHexString.fromText` (UTF-16BE), with a round-trip spec pinning it.

4. **Raster renderer drew v2 highlighters opaque (major).** The PDF annotator
   multiplies highlighter ink regardless of recorded alpha (a v2 highlighter
   records alpha 255), but `renderStroke` gated multiply on `opacity < 1`, so
   page images got an opaque bar over the ink underneath. The raster path now
   applies the same rule; the shading marker still composites normally.

5. **Rotated pages centred ink on the wrong axis.** `rmPointToPdf` centred the
   .rm x axis on `box.width` for every rotation; under 90/270 the displayed
   width is `box.height`, shifting all ink by half the difference on non-square
   pages. Also normalised `/Rotate` into [0, 360) — the spec allows negative
   multiples and `-90 % 360 === -90` in JS. Still untested against a real
   rotated document (none available), but now consistent with the spec.

6. **Settings validation.** The structural merge accepted any same-`typeof`
   value: `imageFormat: "gif"` passed, quality/interval out of range passed,
   and a malformed `syncStore` (array, or missing `notebooks`) would throw far
   from the load site. Now validated/clamped, degrading to defaults.

## Second wave (from the Codex gpt-5.6-sol adversarial pass)

An independent adversarial review (Codex, gpt-5.6-sol, xhigh) over the same
diff confirmed all of the above and surfaced more. Fixed:

7. **Unannotated source documents were never written.** Both the cloud
   pipeline and the .rmdoc import bailed out with "No pages with content
   found" before the output stage, so an imported PDF or EPUB the user never
   drew on produced nothing — with `savePdf` on and success reported. The
   early return now yields to the output stage when a source exists and
   `savePdf` is enabled.
8. **Source-backed documents rendered and buffered every page for a PDF that
   is never assembled.** With `savePdf` on, each page was encoded and pushed
   into `pdfPages`, which the source-backed branch then ignored — a whole
   book's encoded pages held in memory for nothing. Assembly (and the
   per-page render feeding it) is now skipped when a source exists.
9. **Typed-only pages were reported as render failures.** No strokes means no
   stroke bounds, and the renderer returned null — a wholly typed notebook
   synced as "N pages failed to render". Such pages now render as a blank
   standard page (their ink layer genuinely is blank).
10. **Requested outputs that failed only wrote a debug log.** A failed PDF
    assembly or an unannotatable source (encrypted, oversized) reported
    success in the UI. Both now raise a Notice.
11. **The wash path flattened the shading marker's width** to its first
    segment; now the average over the stroke.
12. **Pen taps vanished from annotated PDFs** (single-point strokes were
    skipped); now drawn as dots, matching the raster renderer.
13. **Two weak specs strengthened**: the per-page-size PDF test compared two
    identical images (reusing page 0's box would have passed); the
    single-point-stroke test blessed the data loss.

The rewrite in (1) also resolved Codex's performance finding: a 10,000-item
chain took 12.4 s under the quadratic item-level sort, and takes ~27 ms under
the unit-level sort with a heap.

## Flagged, deliberately not fixed here

- **Document names are not sanitised** for path separators, and a document
  literally named `X (annotated)` can collide with the annotated copy of `X`.
  Pre-existing for page images on `main`; changing it alters existing vaults'
  layouts, so it needs its own decision (relates to #28's wrong-folder theme).
- **Typed text and highlights land in notes as live markdown** — that is the
  feature (wikilinks must work), but it means a hostile source PDF's
  highlighted text could embed remote images. Worth a maintainer decision on
  escaping raw HTML in highlights notes.
- **The 80 MB annotation cap bounds input size, not decompression** — a small
  hostile PDF with huge object streams can still exhaust memory inside
  pdf-lib. Inherent to parsing PDFs in the renderer process; documented.
- **Sync state advances even when a requested output failed**, so automatic
  sync will not retry a failed annotation. Surfacing the Notice mitigates;
  retry semantics are a design decision for the maintainer.

## Open questions

- Rotation handling remains spec-derived; a real rotated scan is still the
  single most useful test document.
- Concurrent multi-device edits tie-break by ascending CrdtId at unit level;
  matches single-device behaviour exactly, unverified against a true two-device
  merge.
