## Attestation investigation (1.4.4 release)

Root cause: **commit/tag skew inherent in release.yml step ordering** — not tampering, not a broken signature.

- Release ran via workflow_dispatch (run 29533968902) at commit `a696a08`. Workflow builds + attests dist/ artifacts FIRST, then creates the version-bump commit `e04ae26` ("chore(release): 1.4.4") and tags THAT commit as 1.4.4.
- The Sigstore cert is bound to source sha `a696a08` on `refs/heads/main`; tag 1.4.4 points to `e04ae26` (whose parent is `a696a08`). Reviewer tooling binds the attestation to the tag's commit → sha/ref mismatch → misleading "signature invalid" wording.
- Attestation is cryptographically valid: `gh attestation verify` exits 0 for all three assets; cert SAN is this repo's release.yml.
- Ruled out: manual re-upload (all assets by github-actions[bot], created_at == updated_at), repo rename (repo id 1175082325 matches cert), post-attestation modification (attest + upload use same dist/ paths back-to-back; prettier ignores dist/).
- **Build-output mismatch is a reviewer-environment artifact**: rebuilding at tag 1.4.4 with pinned bun@1.3.14 (`bun install --frozen-lockfile && bun run build`) reproduces all three released artifacts byte-for-byte (main.js sha256 c90a4cf3…). Though the same tag-vs-built-commit skew (tag contains post-build format/changelog changes) makes the release inherently fragile to rebuild checks.
- Latent hazard: the attest step has `continue-on-error: true` (release.yml:119) — a failed attestation would silently ship unattested artifacts.

## release.yml rewritten: two-phase release (applied)

Key insight superseding the first fix plan: the Sigstore cert binds `github.sha` of the _triggering_ commit — reordering steps inside one run can never make it match a tag created during that run. The build/attest run must be _triggered at_ the tag commit. New design:

- **prepare** job (workflow_dispatch on a branch, `publish=false` — what `release.sh` triggers): validates the version input (semver regex, via env to avoid shell/JSON injection), bumps version/manifest/versions.json, changelog, format, runs `bun run build && bun test` as a gate (never tag a commit that can't build), commits `chore(release): X`, pushes, creates a **lightweight** tag (tag ref points directly at the commit — annotated tags would make `GITHUB_SHA` the tag object on push events), then re-dispatches release.yml at `refs/tags/X` with `publish=true` via the REST API (workflow_dispatch is exempt from the GITHUB_TOKEN recursion guard).
- **publish** job (dispatch-at-tag or manual bare tag push): `github.sha` == tag commit; verifies tag is bare semver (rejects `v` prefix — glob also tightened to `[0-9]*.[0-9]*.[0-9]*`) and matches manifest.json version, builds, attests (**`continue-on-error` removed**), creates the GitHub release.
- Robustness from adversarial review: workflow-level `concurrency: release` group; prepare guarded to branch refs only; idempotent re-run (if HEAD is already `chore(release): X`, skip bump steps — prevents duplicated changelog sections after a partial failure); dispatch-failure recovery command echoed and documented in the header comment.
- `scripts/release.sh` step description updated to match.
