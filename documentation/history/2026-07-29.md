## PR #12 — version-1 line blocks (contributor: vishdhmn)

- Pages written by older reMarkable firmware (version-1 SceneLineItemBlocks) were silently dropped: all point data was parsed with the v2 packed 14-byte layout, but v1 stores 24-byte points (six float32s `x, y, speed, direction, width, pressure` in natural units). Garbage FLT_MAX coordinates crashed `OffscreenCanvas`; `renderPage` swallowed the error and skipped the page.
- Verified against the rmscene reference parser: v1 fields map 1:1 to this plugin's natural units (rmscene multiplies v1 floats into the packed representation; our v2 path divides them back — identical result). Note v1 field order differs from v2 (`speed, direction, width, pressure` vs `speed, width, direction, pressure`).
- Squash-merged as `fix(plugin): parse version-1 line blocks (24-byte float points)`.
- Follow-up hardening: unknown block versions (>2) now log a warning before falling back to the v2 parser instead of failing silently — the same class of bug would otherwise recur for a future v3. Spec added.
- Released as 1.9.1.
