# 2026-08-01

## PDF export plan written

Plan: `documentation/plans/pdf-export.md`. No code yet.

Scoping: "PDF support" was ambiguous across three separate features. User chose **notebook to PDF
export** (an output-format option next to PNG/JPEG/WebP). The other two, syncing PDF-backed
documents and annotation burn-in, are recorded as out of scope in that plan.

Audited the pipeline to answer two questions the user asked directly:

- **Is there PDF export today?** No. `renderPage()` encodes to PNG/JPEG/WebP only and
  `writePageImage()` writes one file per page.
- **Is there annotation-over-PDF today?** No. `downloadDocument()` does fetch the `<id>.pdf` blob
  (it downloads every entry in the document index), but `parseDocument()` only reads `.metadata`,
  `.content` and `.rm`, so the PDF is dropped. A PDF-backed document syncs as ink on blank white
  pages, or reports "No pages with content found" if it was never annotated.

Design calls made in the plan, both wanting confirmation before implementation starts:

- **No new dependency.** Hand-roll a minimal PDF 1.4 writer instead of pulling `pdf-lib` (~380 KB
  minified against a ~129 KB bundle, most of it standard-font data this feature never uses). An
  image-only PDF needs JPEG passthrough as `/DCTDecode` and a zlib stream for the lossless path,
  and `fflate` (already bundled, already blessed by the `fflate/browser` rule) supplies the latter.
  Nothing new for the catalog reviewer to flag.
- **New `savePdf` boolean** rather than adding `'pdf'` to `imageFormat`, which drives both the
  canvas encoder and the file extension.

Settings shape settled with the user: PDF export is a **"Save as PDF" toggle in its own "PDF"
settings section** (`settings/components/pdf-section.ts`), independent of `saveImages`. The
alternative considered first was folding both into an `outputFormat: 'images' | 'pdf' | 'both' |
'none'` enum, which needed a load-time migration of `saveImages: false` and left a "Save images"
toggle sitting next to a dropdown that also offered "Images". Two independent booleans cover the
same four states, need no migration, and match the existing component-per-heading settings pattern.

Open decisions still listed for the user: how a PDF should represent blank pages and pages that
failed to render, since dropping them silently shifts every later page number, and a placeholder
page carrying explanatory text would need an embedded font, which reintroduces the bundle weight
the no-dependency design avoids.
