## Decisions

- Budget constants are fixed, not settings: 8 consecutive failures, 10 min deadline.
- Header entry counts in the index are NOT checked: the second header line's meaning is not confirmed across schema versions, and a wrong check would disable pruning forever.
- #40's path-changing half (sanitising notebook and folder names in the path builders) stays deferred to the next major, per the option-3 split.

## Open (follow-ups from the review, not done)

- A permanently unreadable entry (no `.metadata`, bad JSON, 404) keeps every listing incomplete, so pruning never runs and the banner stays on; failures are not cached, so it costs its retries on every pass. Remember terminal failures by entry hash; name the entry in the banner.
- All-or-nothing downloads can fail forever on one missing blob; auto-sync then re-downloads the other blobs each interval, silently. Back off per notebook or notify once; compare against unique file ids.
- `containVaultFolderPath` treats `\` as a separator on load, so a Linux/macOS target folder containing a literal `\` becomes nested folders (output moves). Document or narrow.
- `deriveSyncStatus` treats an unparseable cloud timestamp as synced forever; warn once per session if it ever happens (e.g. a switch to ISO timestamps).
- Still unverified live: offline panel open keeps `syncStore` and shows the banner; device-edited notebook flips to "Needs sync"; large account lists without bursts; reMarkable's actual rate-limit behaviour.
